# Player Mob Levels Frontend Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add two routes for viewing and editing player-specific mob levels through replaceable asynchronous adapters, using `localStorage` for levels and an empty mob catalog until a CSV is provided.

**Architecture:** Pages load players from the existing `battle_power` table but know nothing about level persistence. A `MobLevelsRepository` owns validation and versioned local-storage serialization, while a separate `MobCatalogRepository` currently returns an empty list and will later be replaced by Supabase. Route components join catalog mobs to per-player levels for display.

**Tech Stack:** TypeScript 5, React 19, TanStack Start/Router, TanStack Query, Supabase JS, Tailwind CSS, Sonner, Node 24 built-in test runner.

## Global Constraints

- Mobs are independent from the existing `heroes` table and must never query or reuse it.
- Valid mob levels are integers from 1 through 30 inclusive.
- The level persistence key is exactly `gvg.mob-levels.v1`.
- Names and image URLs live only in the mob catalog; level records contain only `playerId`, `mobId`, `level`, and `updatedAt`.
- No Supabase schema or migration changes are part of this implementation.
- No fake mobs are seeded; the catalog deliberately returns an empty array until the CSV is supplied.
- Browser storage must not be accessed during server rendering.

---

## File Structure

- `src/lib/mob-levels.ts`: mob and level types, repository contracts, validation, local-storage implementation, and empty catalog implementation.
- `src/lib/mob-levels.test.ts`: unit coverage for storage parsing, validation, upserts, removals, player isolation, and empty catalog behavior.
- `src/lib/mob-levels-ui.ts`: query keys and shared functions for loading players/catalog and resolving stored levels to catalog mobs.
- `src/routes/mob-levels.tsx`: read-only player selector, filter, list, and catalog/player empty states.
- `src/routes/mob-levels.edit.tsx`: draft editor, dirty-state protection, validation, add/remove controls, and persistence.
- `src/routes/index.tsx`: home-page entry for mob levels.
- `src/routeTree.gen.ts`: generated by the TanStack Router plugin during the build; do not hand-edit.

```ts
export type PlayerMobLevel = {

  mobId: string;
  level: number;
  updatedAt: string;
};
export type PlayerMobLevelInput = Omit<PlayerMobLevel, "updatedAt">;

}
export interface MobCatalogRepository { getAll(): Promise<Mob[]> }
```
