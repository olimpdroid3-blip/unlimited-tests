# Проверка проекта после merge

Цель: убедиться, что после слияния изменений ничего не сломалось — без правок кода на этом шаге.

## Что будет прогнано

1. Типы — проверка TypeScript по всему `src/` (включая новые модули `mob-levels*`, `defenses`, `battle-power-ui`, `theme`).
2. Линт — ESLint + Prettier по конфигурации проекта.
3. Тесты — существующие unit-тесты (`mob-levels.test.ts`, `mob-levels-supabase.test.ts`, `defenses.test.ts`, `battle-power.test.ts`, `hero-picker.test.ts`, `nickname.test.ts`, `theme.test.ts`, `test-player-data.test.ts`, `resource-navigation.test.ts`).
4. Сборка — продакшн-сборка, чтобы поймать ошибки бандлинга и SSR/prerender.
5. Быстрая проверка превью — открыть `/`, `/towers`, `/defenses`, `/mob-levels`, `/videos`, `/battle-power` и собрать ошибки консоли.

## Что будет в отчёте

- Результат каждой проверки: прошло / упало.
- Для падений — файл, строка, текст ошибки и причина (тип, логика, конфигурация).
- Отдельно: предупреждения линта, которые не блокируют сборку.

## Правки

На этом шаге правок нет. Если что-то падает, я показываю список ошибок с предложением исправления и жду подтверждения — бизнес-логику из merge не трогаю без согласования; чиню только то, что реально ломает сборку/типы.
