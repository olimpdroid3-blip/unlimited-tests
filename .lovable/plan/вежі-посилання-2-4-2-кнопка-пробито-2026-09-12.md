# Вежі: посилання 2.4.2 + кнопка «Пробито»

## 1. Чому зникло посилання на вежу 2.4.2

Джерело вежі 2.4.2 у сховищі є (повідомлення 26212, збережено 13:21 за Києвом), але список,
опублікований тієї ж хвилини, прочитав **застарілу кешовану копію** файлу джерел — тому рядок
2.4.2 вийшов без посилання, а старіші вежі (1.4.1, 3.6.1) посилання мають.

Виправлення: читати файл джерел завжди «свіжим» (обхід кешу + запис без кешування).
Після цього кожна щойно додана вежа одразу отримує клікабельне посилання.

## 2. Нова кнопка «Пробито» під записом вежі

Зараз під записом бота одна кнопка. Стане так:

```text
🏰 Вежа 2.4.2
Код вежі: 2.4.2
Нік: Fakra
Коментар: ...
┌─────────────────────────────┐
│        💥 Пробито           │   ← нова
├─────────────────────────────┤
│      🗑 Видалити запис      │
└─────────────────────────────┘
```

Після натискання «Пробито» — підтвердження (як у видалення):

```text
┌──────────────────┬──────────────┐
│ ✅ Так, пробито  │    ❌ Ні     │
└──────────────────┴──────────────┘
```

- «Ні» — повертає звичайні дві кнопки, нічого не змінюється.
- «Так» — запис вежі **залишається** (нік, скриншот, коментар), вежа позначається як пробита.

## 3. Як це видно у загальному списку

```text
🏰 Вежі

🏰 Вежа 1.4.1 — Fakra
🏰 Вежа 2.4.2 — Fakra  ❌
🏰 Вежа 3.1.1 — romio_kyiv
```

Червона позначка `❌` — ознака «пробито» (у Telegram немає червоної галочки, це найближчий
червоний символ; можу замінити на 🔴 або ☑️ на ваш смак).

## 4. Оновлення списку

Після підтвердження «Пробито» бот одразу публікує оновлений список усіх виставлених веж,
а попередній список видаляє — рівно так само, як це вже працює після додавання й видалення вежі.

## Технічні деталі

- `src/lib/tower-origin.server.ts`: читання стану через свіжий запит (cache-busting + `no-store`),
  запис із `cacheControl: "0"`.
- `src/lib/tower-origin.ts`: колбеки `tower:breach:*` (запит / так / ні) + позначка в рядку списку.
- `src/lib/gvg-tower-notify.server.ts`: клавіатура запису з двох рядків, підтвердження «Пробито».
- `src/lib/gvg-tower-form.server.ts`: обробка колбеків (лише адміністратори), оновлення
  `towers.breached` через існуючу модель статусів, далі `handleTowerListCommand()`.
- `src/lib/gvg-tower-list.server.ts`: пробиті вежі залишаються у списку з позначкою (зараз вони
  з нього відфільтровані).
- Тести на нові колбеки та рендер рядка списку.
